1 Ringkasan & Arsitektur Alur Transaksi

Layanan API ini memungkinkan aplikasi pihak ketiga (3rd Party Application) untuk membuat QRIS Dinamis (Paydia QRIS) menggunakan kredensial produksi Faspay atas nama entitas PT Rasa Distribusi Indonesia (RDI). Layanan ini dilengkapi dengan Webhook Relay System yang secara otomatis meneruskan konfirmasi pembayaran sukses ke endpoint pihak ketiga secara instan.

1
Aplikasi Pihak Ketiga → Rasa Connect: Request Generate QRIS
Kirim `reference_no`, `amount`, `callback_url`, dan `callback_token` via endpoint `POST /api/v1/external/qris/rdi/generate`
↓
2
Rasa Connect → Faspay SNAP BI: Standalone QRIS RDI
Sistem membuat QRIS dinamis via Faspay SNAP RDI (Merchant ID 37020) dan memperoleh direct image URL PNG.
↓
3
Customer Melakukan Pembayaran
Customer memindai QR code dari aplikasi pihak ketiga menggunakan BCA, Mandiri, GoPay, OVO, Dana, dll.
↓
4
Faspay Payment Gateway → Rasa Connect Webhook (Status 00 Verified)
Faspay mengirimkan notifikasi verifikasi pembayaran lunas ke webhook endpoint Rasa Connect.
↓
5
Rasa Connect → Aplikasi Pihak Ketiga: Webhook Relay Real-Time
Sistem Rasa Connect meneruskan data pembayaran sukses ke `callback_url` pihak ketiga dan membalas status 200 ke Faspay.

2 Autentikasi API

Setiap panggilan API dari pihak ketiga wajib menyertakan header keamanan berikut:

Header Name Nilai (Value) Keterangan
X-API-KEY rasa_qris_rdi_sec_2026! Kunci otentikasi rahasia sistem eksternal
Content-Type application/json Format request body (JSON)
Accept application/json Format respon yang diharapkan

3 Spesifikasi API Endpoint

3.1. Generate QRIS Dinamis (Dedicated RDI)

Endpoint ini digunakan untuk men-generate gambar QRIS untuk nominal tertentu dan mendaftarkan URL webhook pihak ketiga.

  • Method: POST
  • URL: https://rasaconnect.com/api/v1/external/qris/rdi/generate
Parameter Tipe Wajib? Keterangan
reference_no String Wajib ID referensi / nomor invoice unik dari sistem Anda (maks. 64 karakter).
amount Numeric Wajib Nominal transaksi dalam Rupiah (min. 1000). Contoh: 50000.
callback_url String (URL) Opsional URL webhook pihak ketiga yang akan di-hit otomatis saat pembayaran sukses diverifikasi.
callback_token String Opsional Token / kunci rahasia pihak ketiga yang akan dikirim kembali via header X-Callback-Token.
customer_name String Opsional Nama pelanggan (default: "Customer").
customer_phone String Opsional Nomor telepon pelanggan.
description String Opsional Catatan transaksi (default: "Payment #{reference_no}").
validity_minutes Integer Opsional Masa berlaku QR code dalam menit (default: 60 menit).
format String Opsional Pilihan respon: "json" (default), "image" (stream binary PNG), atau "redirect".
Contoh Request cURL:
curl -X POST https://rasaconnect.com/api/v1/external/qris/rdi/generate \
  -H "Content-Type: application/json" \
  -H "X-API-KEY: rasa_qris_rdi_sec_2026!" \
  -d '{
    "reference_no": "INV-APP3-00123",
    "amount": 50000,
    "customer_name": "Ahmad Fauzi",
    "customer_phone": "081234567890",
    "description": "Pembayaran Invoice INV-APP3-00123",
    "callback_url": "https://api.pihakketiga.com/webhook/payment",
    "callback_token": "token_auth_pihak_ketiga_xyz"
  }'
Contoh Respon JSON (HTTP 200 OK):
{
  "status": "success",
  "responseCode": "2004700",
  "responseMessage": "QRIS generated successfully",
  "data": {
    "id": 1,

PENTING: Nilai data.qr_image_url adalah URL file gambar PNG langsung. Anda dapat langsung menggunakannya pada tag HTML <img src="..." /> di website atau Image View di aplikasi kasir/mobile Anda.

4 Spesifikasi Webhook Pihak Ketiga (Receiver)

Ketika pembayaran customer telah berhasil diverifikasi oleh Faspay, server Rasa Connect akan otomatis mengirimkan request HTTP POST ke callback_url milik Anda.

4.1. Header Request Webhook yang Dikirimkan:

Header Name Contoh Nilai Keterangan
Content-Type application/json Format data JSON
User-Agent RasaGroup-Webhook-Relay/1.0 Identitas pengirim webhook
X-Event payment.verified Event pembayaran terverifikasi lunas
X-Timestamp 1791708522 UNIX timestamp waktu dispatch
X-Callback-Token token_auth_pihak_ketiga_xyz Nilai callback_token yang Anda daftarkan
X-Signature 77b6758b1e13f0505... HMAC-SHA256 signature untuk validasi keaslian payload

4.2. Rumus Validasi Signature:

Untuk memvalidasi keaslian data pada server Anda (opsional tapi disarankan):

expected_signature = hash_hmac('sha256', header['X-Timestamp'] + '.' + raw_json_body, callback_token)

4.3. Body Payload Webhook (JSON):

5 Contoh Kode Webhook Receiver (Pihak Ketiga)

Contoh Node.js (Express.js):

const express = require('express');
const app = express();
app.use(express.json());

app.post('/webhook/payment', (req, res) => {
    const token = req.headers['x-callback-token'];
    
    // 1. Verifikasi callback token
    if (token !== 'token_auth_pihak_ketiga_xyz') {
        return res.status(401).json({ error: 'Unauthorized token' });
    }

    const payload = req.body;
    if (payload.event === 'payment.verified' && payload.status === 'paid') {
        const referenceNo = payload.reference_no;
        const amount = payload.amount;

        // 2. Tandai invoice di database internal pihak ketiga menjadi LUNAS (PAID)
        console.log(`[SUKSES] Invoice ${referenceNo} sebesar Rp ${amount} telah LUNAS.`);
    }

    // 3. Wajib balas HTTP 200 OK
    return res.status(200).json({ status: 'success' });
});

app.listen(3000, () => console.log('Webhook server running on port 3000'));
